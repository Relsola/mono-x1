# 移动组件回归：**斜轴平台驮着角色走完一个来回**
# 第二世界那块平台：a = (1408, -1216)、b = (2304, -960)、speed 320、方形（96 x 16 半宽高）
# 验证：
#   ①大地图传送到 `SECOND 2`（1312, -1408）—— 顺带覆盖「进入世界会重建移动组件」
#   ②走到平台正下方，二段跳落到它上面（grounded 必须是 1）
#   ③骑着它走：每帧位移 = 轴向量 * (320/60/轴长)，**两个分量都跟得上**
#     （轴长 931.85 → 每帧 (5.13, 1.47)，与实测一致）
#   ④**到端点反向之后仍然站在上面** —— 这是 2026-09-25 修掉的那个 bug 的现场：
#     驮人判定如果用「移动之后」的矩形，平台**朝下走**的那一段会被判成「没接触」，
#     角色被留在原地直接掉下去（表现：这一刻 grounded 变 0 / state FALL）。
#     用例里 f430~f480 经过一次反向（t=0 端）、f620~f660 经过第二次（t=1 端），两次都断言 grounded 1
# 为什么必须用斜轴：竖直轴上「朝下走」也可以被上升段盖住而看不出来，只有带竖直分量、
#   而且要走完一个来回，才能拓出「驮人判定要用移动前的几何」这条 —— 只测上升段会漏掉。
# 帧号与平台相位强耦合（传送那一步会把组件的 t 归零，所以相位是确定的）：
#   改平台端点 / 速度 / 尺寸 / 改传送点 / 改二段跳初速之后必须重新取样（F7）。
# 运行：build\main.exe input_script test\mover_ride.txt（在仓库根启动）
# ============================================================
