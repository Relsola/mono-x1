# ============================================================
# 大地图 UI 回归：开图 → 世界暂停 → 选项 → 确认传送 → 关图 → 传回 → 鼠标
# 候选项 = **所有世界的传送点**（两张图各摆 2 个，都站在地面上 ⇒ 列表 4 项）：
#   item 0 = `FIRST 1`  (544,  -1408)（脚底坐标）   item 1 = `FIRST 2`  (1056, -1408)
#   item 2 = `SECOND 1` (800,  -1408)               item 3 = `SECOND 2` (1312, -1408)
# 四个落点互不相同、而且跨世界 —— 所以「选中项 → 落点」这条链每个 item 都能单独验。
# 验证：
#   ①GA_MAP（Esc）开图：世界**完全暂停** —— 按住**冲刺**（F）也一格不动（「打开 = 世界暂停」的直接证据）。
#     用冲刺而不是方向键：方向键在图里有含义（改选中项），两者混在一起就分不清是哪一个在起作用
#   ②图内方向键改的是**选中项**：不确认就不传送
#   ③GA_JUMP 确认 = 落到选中传送点的脚底位置（本世界内与跨世界都验到）
#   ④鼠标：悬停即选项、左键落在某项上 = 确认；停在列表外点一下什么都不做
#   ⑤开图时选中项对齐到**当前世界的第一个传送点**（所以关掉再开，光标还在我这一屏）
# 两个刻意的依赖，改键位/词表/布局/传送点时都要一起看：
#   - **鼠标坐标是客户区像素**，而列表按客户区尺寸居中排：下面这些坐标按默认全屏（3840x2160、
#     ui_scale = 3）算出 —— 项宽 960、项高 264、间距 48、4 项整列高 1200，所以顶边 y = 480；
#     x 都是 1440..2400，item 0..3 依次覆盖 y 480..744 / 792..1056 / 1104..1368 / 1416..1680。
#     换显示器分辨率或给 main.exe 加 `--window` 之后这些数字必须重新算（实测过：加
#     `--window 1280x720` 跑本用例必挂，因为客户区尺寸变了）
#   - 标签是「世界名 + 序号」：世界名来自 game_world_name，序号来自数组下标（资产里没有字符串）
# 运行：build\main.exe input_script test\ui_map.txt（在仓库根启动）
# 帧号与坐标与关卡强耦合：改传送点 / 改按键 / 改落点后必须重新取样（F7）
# ============================================================
