# DirectX 11 学习工程

这是一个使用 Win32 Unicode API 与 C 风格 C++ 编写的 DirectX 11 和 2D 游戏开发学习工程。

> 游戏类型暂时模仿为 空洞骑士、蔚蓝、时空幻境、推箱子 这种 2D 类银河恶魔城带解谜游戏 

这个工程不以最终目标实现为需求，而是探索从零学习并理解 DX11 和 这种 2D 游戏开发需要的知识。

当前目标是先建立清晰、可调试的最小渲染框架，再逐步补齐渲染管线中的各个部分。

## 当前学习进度

- 创建一个 Win32 Unicode 窗口，使用 PeekMessageW 驱动非阻塞的游戏主循环。
- DX11 交换链、纹理、阿尔法混合
- 图像解码与精灵图：`stb_image` 解 BMP/PNG → 纹理句柄，支持 11 帧循环动画与水平翻转
- 相机跟随、世界坐标、NDC 坐标归一化
- AABB 重叠检测 和 碰撞箱可视化调试
- XAudio2 音频系统（两级总线树、voice 池、回调驱动的槽位回收、2D 等功率声像与反距离衰减）
- 真实素材解析（dr_wav 解 WAV / stb_vorbis 解 OGG）与**流式加载**：短音效常驻解码后的 PCM（起播零延迟），长音频只常驻压缩数据、播放时由音频线程按块解码（140 秒 BGM：47MB → 3.5MB，加载 330ms → 1.3ms）
- 角色朝向、动作状态机与冲刺（快速水平位移，仍走轴分离碰撞）
- 分层解耦：渲染层（纹理句柄 + 帧绘制列表）、输入层（后端函数指针 + 粘滞边沿）、相机（只根据数据更新）、关卡（`LevelAsset` 二进制 tile → 碰撞体数组）
- 平台跳跃角色运动：重力、二段跳（地面那一段不消耗次数，空中还能再跳一次）、冲刺、土狼时间、跳跃缓冲、抗锯齿无关的单向平台（可下穿）
- 输入双后端：GameInput（首选）失败时自动降级为「窗口消息 + XInput」；其上还有一层**磁带**（录制 / 回放 / 文本脚本共用同一份执行路径），可无焦点自动化验证
- 输入脚本回归：`input_script <路径>` 从存档点开始回放输入并校验游戏状态，跑完自动退出并返回退出码
- 存档系统（正式系统）：`GameStateSnapshot` + 三重校验（版本 / 关卡几何指纹 / 校验和），磁带的世界可复现性建在它上面

- 碰撞盒 70x90 像素（相对 128 像素精灵取 0.55x0.7，盒底对齐精灵脚底）
- 数值：跑速 640 px/s、重力 4200 px/s²、跳跃初速 1430 px/s（单跳顶点约 243 像素）、二段跳（空中那下同初速，两段合计约 461 像素）、冲刺 1600 px/s x 0.15s（位移 240 像素）、能量波 2400 px/s（发射冷却 1 秒，最多 8 枚并行）
- 伪时停原型：以发动位置为中心的 448px 圆形范围持续 3 秒，冷却从发动起共 5 秒；接触范围的活动平台和怪物降至 8% 速度，范围以灰白蒙版显示且不覆盖主角
- 第二世界：短地刺、移动组件（方形可站可驮、圆形碰到就伤害），以及一个固定向左行走、跨过缺口后掉落重生的色块怪物；怪物碰撞盒接触角色会造成重生
- 关卡目前有两个预载世界：编辑语义保存在 `data/map/*.bin`（tile：`.` 空、`#` 实体、`=` 单向平台、`P` 出生点），启动时合并成尽量少的矩形碰撞体；资产格式与游戏数据流见 `docs/level-assets.md`
  - 第一世界右下方有两格高门洞；角色碰撞盒完全通过后进入第二世界，期间按基础跑速自动走到入口落点、锁定输入且无敌。这段时间也是后续异步加载目标世界资源的预算窗口
  - 第二世界有一段地刺、水平往返的实体平台和会掉入缺口或被能量波命中后重生的色块怪物。地刺视觉是锯齿、只有半格高（看起来埋在地面里），但伤害判定是一整格矩形；地刺或怪物触碰角色后都会回到第二世界入口出生点
  - **移动组件**是通用的「可循环移动件」：**形状（方形 / 圆形）+ 一条轴（两个端点，可任意方向）+ 沿轴速度**，每张图可以放多个（上限 8）。它**先朝 B 走**、到端点反向；速度是**沿轴**的 px/s 而不是某个分量，所以竖着、斜着的每帧位移与水平放同一套公式。本体**按定义就在轴上**（资产里存的是轴上的参数 `t0`，不是绝对坐标，所以「本体飘在轴外」这种状态存不下来）。**方形**：可站、驮着走（两个轴都驮）；勾上「被挤住会伤害」就是**被挤住 / 压住**时回出生点（驮着走依然安全 —— 实测：不伤害时被压在原地 309，伤害时回出生点 288）。**圆形**：不可穿过、**不驮人**，恒定伤害 —— 碰到就回出生点（实测：冲刺撞上去回出生点 288，同一位置换成方形只被挡住 404.8）
  - 第一世界第三个坑上架了一座**可消失的桥**（tile `V`）：站上去先变暗预告 2 秒（此时还能站），然后消失成半透明的虚影（不可碰撞），掉下去会直接掉出关卡重生；再过 2 秒恢复成实体。触发要**连续踩住约 0.17 秒**（蹭一下、斜穿一格都不算），之后**不可回退**：一旦开始预告就一定消失，离开也救不回来。相位与计时器进存档快照，能在 `test/vanish_bridge.txt` 里自动化重现
  - 第一世界有一对**传送门**（同色互传，颜色 = 配对键 = 调色板下标）：**角色中心站在门里时按上键（↑/W）**才触发，站着不动不会自己传；落点是「角色水平中心对齐门中心、脚底贴门矩形底边」，所以编辑器里把门贴地摆好落点自然站得住（门埋进墙里时会先顶上最近那层地面顶面）。传送期间锁输入、分三段（淡出 0.3s → 加载 0.4s → 淡入 0.3s），加载段会在目标门上方放一个两帧交替的转圈标记。外观是**一张灰度门贴图 + 逐项 tint**（tint 取调色板，所以一对门同色、编辑器里看到的就是游戏里看到的），多帧条带与着色都走渲染层的 `SpriteStyle`（见 `docs/d3d12-renderer.md`）。面板与相位（含目标门下标）进快照，见 `test/portal_pair.txt`
  - 左侧 col 1-3 有一座每 3 格一层的攀爬塔，能一路跳到接近顶部
  - **大地图 UI**（ESC / 手柄 Start，同一个键开关）：打开时**整个世界暂停**（不吃输入、不走物理、不动动画）——
    压暗背景 + 一列候选项 = **所有世界的传送点**（编辑器里摆的实体，每图最多 4 个；现在两张图各摆 2 个），
    每项写着「世界名 + 序号」（如 `SECOND 2`），底部一行操作提示；
    方向键选项、跳跃键确认 → 落到那个传送点；也可以**鼠标悬停选项 + 左键确认**（UI 打开时光标会显示）。
    文字走**自制的 5×7 点阵字体**（`include/font.h`：字形表 → 图集 → uv 子矩形 + tint，见 `docs/d3d12-renderer.md`
    的 SpriteStyle）—— 现在只有 ASCII 大写/数字/少量符号（小写映射成大写），要中文得换一张含 CJK 的图集。
    UI 是**自研**的（不把 ImGui 引进游戏运行时）：
    逻辑跑在固定步长里，所以磁带/回放能驱动它；状态进快照；绘制走渲染层的**屏幕空间矩形**
    （`renderer_push_ui_rect` + `LAYER_UI`，见 `docs/d3d12-renderer.md`）。见 `test/ui_map.txt`
- 背景音乐 `Memories of the School.ogg` 在启动时**以流式方式**起播并无限循环（不预先解码整段）

### 音频素材加载约定

| 类型 | 策略 | 内存 | 起播 |
| --- | --- | --- | --- |
| 短音效（coin / button） | 常驻解码后的 f32 PCM | 0.42 MB | 零延迟 |
| 长音频（BGM） | 只常驻压缩数据，音频线程按块（4096 帧 ≈ 93ms）解码 | 3.54 MB | 首块解码后（<1ms） |

## 回放调试按键（MONO_DEBUG_INPUT）

| 按键 | 作用 |
| --- | --- |
| F5 | 录制：第一次按下开始（同时把当前状态写成存档点 `build/replay_state.sav`），第二次按下结束并自动导出脚本 |
| F6 | 回放：第一次按下循环回放（本次会话录的那盘，否则最近导出的脚本），第二次按下停止 |
| F8 | 断言标记：把当前这一步的玩家状态与世界状态写进磁带（位置/动作/落地/世界，四条断言） |
| F4 | 再导出一份 `build/replay_script.txt`（例如回放途中补了 F8 标记之后） |

（音频没有专用调试按键：早期那套 F8/F9/F10 生成音按键已随“程序生成测试音”方案一起删除；F8 现用于断言标记。）

> 注意：键盘 E / F 走 GameInput 时注入式按键会被过滤（GameInput 读 Raw Input）。
> 需要自动化验证时用 `input_script test/baseline.txt`：磁带在输入后端**之上**接管整帧输入，两种后端都生效。
> 要连“真实设备输入”都能被外部程序驱动（例如自动化录制 → 导出带断言的脚本），就用 `--input win32`。

## 调试输出

| 开关 | 作用 |
| --- | --- |
| `--load <路径.sav>` | 启动即读档（存档系统是正式系统，不受调试宏影响）。与 `input_script` 同时用时以脚本的存档点为准 |
| `input_script <路径.txt>` | 显式加载输入脚本；不传时正常手动游玩。脚本第一行必须给存档点（`save <路径.sav>` 或 `save spawn`）；载入失败立即以退出码 1 收摊 |
| `--input <auto\|gameinput\|win32>` | 选输入后端（默认 `auto`）。`win32` 走窗口消息 + XInput，**外部程序能用 `PostMessageW` 注入按键**，是“自动化录制 → 导出回归脚本”的前提 |
| `--camera <default\|precise>` | 强制相机档位（调试用，A/B 对比跟随手感）：`precise` = 竖直带死区，小跳/走路起伏不带动画面 |
| `--trace <路径.csv>` | 每逻辑步输出一行状态（坐标/速度/动作状态/各计时器/输入位掩码/**相机位置与缩放**），列定义见 `include/debug/trace.h` |
| `--window [宽x高]` | 以窗口模式启动（默认 1280x720，放在屏幕左上角）；不传则无边框全屏。窗口模式便于多窗口调试与截图验证 |
| `--fast` | 逻辑步不吃真实时间（每循环正好一步）且每 64 帧才 Present 一次：**只给磁带回归用**。实测 1961 帧从 33 秒降到 **1.0 秒**（瓶颈是 `Present`），且与实时模式的逐帧轨迹**逐字节一致** |

- 输入源互斥：同一时刻只有「真实设备 / 磁带」之一在驱动输入；磁带在跑时 `F5`（录制）与 `F6`（换一盘）会被拒绝并 `WARN`
- 碰撞盒可视化（MONO_DEBUG_VIS）：青=关卡实体、绿=单向平台、黄=玩家物理盒、洋红=地面探针
  （探针是玩家盒下移 1 像素的副本，被画成脚底那条色带；其余是中空线框）。
  这些盒由碰撞/游戏侧**上报**（`debug_vis.h`），装配层统一绘制 —— 新实体只要登记了碰撞盒就自动有线框，
  而且画的是物理盒而不是插值后的渲染盒
  - 红=地刺、橙=移动组件（含圆形）、粉=怪物；关卡切换时静态调试盒会先清空再登记新世界，避免旧世界线框残留
- 磁带（录制回放 + 输入脚本）：`F5` 录一段、`F8` 在关键节点标记、再按 `F5` 结束即得到可直接重跑的回归用例
  （第一行是存档点 `save build/replay_state.sav`，后面是输入变化点与断言；“手工调手感”因此能一键沉淀成自动化测试）
  - 能稳定复现的原因是**存档系统**：磁带只存「存档点引用 + 输入 + 断言」，世界由 `.sav` 恢复（见 `docs/save-system.md`）
  - 录制的是真实设备输入：GameInput 读 Raw Input，注入式按键会被过滤（与上面那条注记是同一个原因）
  - 存档带**关卡几何指纹**：改了关卡后旧存档/旧磁带会被拒载并提示重新生成，而不是跑出一个无从排查的差异
  - 脚本还可用 `assert_world FIRST|SECOND` 校验当前世界，用 `assert_transition 0|1` 校验普通门的锁定输入、无敌自动走入阶段
  - 回归怎么跑（`test\run_tests.bat`，**串行**，一次一条）：
    - `test\run_tests.bat baseline.txt`：跑单个用例，**实时**（人看着渲染，不写 trace）
    - `test\run_tests.bat baseline.txt fast`：单个用例，快速 + 确定性守卫
    - `test\run_tests.bat all fast`：全部用例，快速 + 守卫 —— **AI/自动回归用这条**（实测 2 条 × 2 遍 ≈ 2.0 秒）
    - `fast` 还有第二层含义：每条用例**跑两遍、逐字节对拍两遍的 `--trace`** —— 那是**确定性守卫**，
      拓「没进快照却仍影响逻辑」的状态；它**不是性能测试**，只是 fast 要跑两遍的原因
    - 参数不能带引号：`main.exe` 按空白切分命令行且不去引号；VS Code 里跑 `test` 任务（= `all fast`，先构建）
  - 常驻用例：`test/baseline.txt`（出生点走一遍全部动作，53 条断言）、`test/save_roundtrip.txt`
    （`save_state` → 接着跑 → `load_state` 回那一刻的往返断言）、`test/smoke.txt`
    （关卡冒烟：**不依赖具体坐标与几何**，改完关卡之后它仍应该通过，所以它能用来回答
    “这张刚编辑过的图主程序能不能真的加载并跑起来”）、`test/vanish_bridge.txt`
    （可消失平台的三态：站上去 → 变暗预告 → 消失掉出关卡重生 → 恢复后能重新走过）与
    `test/portal_pair.txt`（传送门：按上键 → 落点对齐 + 判据是中心 → 再按一次能传回）、
    `test/ui_map.txt`（大地图：开图后世界暂停 → 方向键选项 → 确认落到选中世界的出生点 → 能传回）与
    `test/mover_ride.txt`（移动组件：大地图进第二世界 → 二段跳上那块**斜轴**平台 → 被驮着走完一个来回，
    两次端点反向都断言还站在上面 —— 它就是「驮人判定必须用移动前的几何」这条的回归）。
    中途起点用例用同一段脚本里的
    `save_state` + `load_state` 就能写，不必再维护“写/读”两个文件）
  - 编辑器菜单里的「保存并试玩 / 保存并冒烟验证」就是起一次 `build\main.exe`（后者跑 `smoke.txt`），
    见 `editor/README.md` —— **不是热重载**：游戏启动时只读一次 `.bin`，改完必须重起

## 其它

1. 构建：先跑一次 `shell.bat`（内部 `call vcvars64` 后 `cmd /k`，得到一个 `cl` / `fxc` 都在 PATH 的终端），在其中跑
   `build.bat`（默认 debug 档 = 回归跑的那一档）/ `build.bat release`（发布档：`/MT /O2 /DNDEBUG /GL /LTCG`，
   四个调试宏全关 —— 它只用于出包或真实性能测试，所以 **assert 在 release 里是不存在的**）/
   `build.bat shaders`（只重编着色器，**改完 shader 必须跑一次**）。**三种模式都会重编着色器**：运行期读的是
   预编译好的 `build\shaders\*.cso`，渲染层不在启动时编译 HLSL。产物是 `build\main.exe`，
   **在仓库根启动**（`build/shaders/*.cso` 与 `data/` 都按进程工作目录解析）

    - 这个渲染问题本身的来龙去脉、业界各种解法与资料来源整合见 `docs/pixel-jitter.md`（学习向，含历史与逐条可信度标注）

10. 存档系统（正式系统：文件格式、三重校验、关卡指纹、会丢什么）见 `docs/save-system.md`
11. 源码分层：`main.cc` 只负责装配（窗口 + 初始化 + 主循环骨架）；`src/scene.cc` 负责场景装配（程序化占位贴图 + 每帧绘制提交）；`d3d12_renderer.cc` 是唯一出现 D3D12/DXGI 类型的地方；包含平台头的编译单元只有 6 个（装配层 `main.cc` + 实现层 `d3d12_renderer.cc` / `audio.cc` / `platform_win32.cc` / `win32_input.cc` / `gameinput_input.cc`）；`win32_input.cc` / `gameinput_input.cc` 是两个可替换的输入后端
    - `include/` 下的公共头一律不含平台头（需要窗口句柄就用 `void *`，见 `input.h` / `renderer.h`；音频实例用前向声明 + 不透明指针，见 `audio.h`）
    - 要用 `<windows.h>` 就包含 `include/win32_prefix.h`（它统一定义 `WIN32_LEAN_AND_MEAN` / `NOMINMAX`），且只允许在 `.cc` 里包含
    - 基础模块：`core.h`（类型/数学/哈希，两边共用）、`shared/memory.h`（线性分配器 + `Array`）、`shared/file.h`（文件 IO + UTF-8 路径转换）、`shared/collision.h`（AABB，两边共用）、`sprite.h`（精灵与动画）、`input.h`（动作语义 + 后端表）、`save.h`（存档，正式系统）；关卡层与资产格式在 `shared/level.h` / `shared/level_asset.h`
    - 调试模块（`debug_vis` / `trace` / `replay` / `input_script`）与普通模块**同级**：头在 `include/debug/`、实现在 `src/debug/`
      （引用写全路径 `#include "debug/replay.h"` —— 目录名要能一眼看出文件在哪），
      各自用 `MONO_DEBUG_*` 宏在**头内部**自包含门控（关掉时全部展开为空）→ 所以包含点不需要写 `#if`
      - `replay` 现在装的是**磁带**（存档点 + 输入变化点 + 断言）与它的执行引擎 —— 录制、回放、脚本共用这一份；
        `input_script` 只剩「文本 ⇄ 磁带」两个方向的读写

12. 协作须知与已知坑清单：`AGENTS.md`（分层铁律、已踩过的坑、验证方式、文档约定、明确搁置的"死代码"）
## 注意点

1. 一些宏定义（互相独立，按需开关；关闭时调用点被宏展开为空，运行期零成本）
    - `MONO_DEBUG_TMP` 临时用于验证或辅助的代码（当前无代码使用，留作约定）
    - `MONO_DEBUG_VIS` 碰撞盒线框
    - `MONO_DEBUG_BUILD` `--trace` 轨迹文件 + XAudio2 内部告警
    - `MONO_DEBUG_INPUT` 输入脚本（注入 + 断言）、F7 取样、录制回放（F4/F5/F6/F8）
    - `MONO_DEBUG_ANY`（派生宏，不用手动设）上面任意一个开着就为 1：`LOG_DEBUG` 与调试期的窗口置顶用它
    - 日志：`LOG_INFO` / `WARN` / `ERROR` 永远在；`LOG_DEBUG` 跟着 `MONO_DEBUG_ANY`

2. 使用当前支持的稳定新 API 而不过时的旧模板代码
