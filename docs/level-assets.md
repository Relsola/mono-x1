# 关卡资产（LevelAsset）

涉及文件：`include/shared/level_asset.h`、`src/shared/level_asset.cc`、`include/shared/level.h`、`src/level.cc`、`include/game.h`、`data/map/*.bin`。

> 2026-09-25：`Level` / `WorldId` / `PlayerFacing` / `WorldConnection` 从 `include/game.h` 移到了
> `include/shared/level.h`（编辑器诊断也要 `Level`，而它不该为了一个结构体包含整个 `game.h`）。
> 同一轮把编辑器也在用的头（`collision.h` / `memory.h` / `file.h`）一起收进了 `include/shared/`。
> 网格 ↔ 世界的换算公式也收在 `include/shared/level_asset.h` 的五个 helper 里。

> 目录名 2026-09-22 从 `data/levels/` 改为 `data/map/`（编辑器与游戏共用同一批路径常量与扫描规则）。

## 1. 数据流

```
独立编辑器（editor\build.bat -> build\editor.exe）
  level_asset_load()  -> LevelAsset
  level_asset_validate() -> 语义问题列表（有 ERROR 就拒绝保存）
  level_asset_save()  -> data/map/*.bin（写临时文件 -> 读回来逐字段比对 -> 原子替换）

main.exe
  level_asset_load() -> LevelAsset（编辑语义、arena 常驻）
  level_build_from_asset() -> Level（静态碰撞与世界边界）
  Level + 出生描述 -> GameState（玩家、移动组件、怪物等运行态）
```

`LevelAsset` 是编辑器和游戏唯一共享的关卡层：tile、地刺、门、移动组件出生描述和怪物出生描述都在这里。
`GameState` 的速度、计时器、相机、伪时停、能量波和活动实体当前位置都是运行态，绝不写回 `.bin`。

## 2. 文件格式（版本 2；版本 1 只读兼容）

所有数值为小端、紧密按字段写入；**不是 C++ 结构体内存镜像**。加载器逐字段解析，因此 padding、指针和容器布局不会进入格式。

| 顺序 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `magic` | `u32` | `0x314C564C`，文件字节是 `LVL1` |
| 2 | `version` | `u32` | 当前为 `7`；reader 接受 `1`..`7` |
| 3 | `tile_columns` / `tile_rows` | `u32` × 2 | tile 网格尺寸 |
| 4 | `tile_size` | `f32` | 世界像素 |
| 5 | 实体数量 | `u32` × 3（v1..v3）/ × 4（v4）/ × 5（v5+） | 依次是门、移动平台、怪物（、传送门、传送点） |
| 6 | tile 段 | `u8` × 宽 × 高 | row-major：`.` / `#` / `=` / `P` / `^` / `V` |
| 7 | 门段 | `u32,u32,f32,f32,u32` / 项 | 边（左/右）、目标关卡 ID、脚底落点 x/y、朝向 |
| 8 | 移动组件段 | `f32` × 7 / 项（v1..v5）；`f32` × 9 + `u32` / 项（v6）；`f32` × 8 + `u32` × 2 / 项（v7+） | v7：两点 x/y + `t0` + 半宽半高 + 沿轴速度 + 形状 + 伤害开关 |
| 9 | 怪物段 | `f32` × 7 / 项 | `Rect2D` + 出生 x/y、出生速度 x |
| 10 | 传送门段（v4+） | `f32` × 4 + `u32` / 项 | `Rect2D` + 配对角标（调色板下标，同色 = 一对） |
| 11 | 传送点段（v5+） | `f32` × 2 / 项 | **脚底** x/y（一个点，不是矩形） |

加载器会校验 magic、版本、非零网格/格尺寸、精确文件长度、门枚举范围及平台范围；不通过则拒绝加载。

**版本 1 → 2 的迁移**（地刺从「矩形实体段」改成一种 tile）：v1 的头多一个 `u32`（地刺数量）、
tile 段后面多一段地刺矩形。reader 仍能读 v1，并在读入时把每个地刺矩形换成**格中心落在矩形内**的地刺格
（相邻格不动：一格只能装一种东西；真的撞上时会留一条 WARN）。所以在编辑器里打开旧图 → 另存为，就升级成 v2。
头长度因此不同（v1 = 8×`u32`+`f32` 共 36 字节，v2 = 7×`u32`+`f32` 共 32 字节），
`level_asset_compute_size()` 按版本算，两边共用同一份算法。

**版本 3 → 4 的迁移**（新增实体「传送门」）：header 多一个数量字段（四类实体），
tile 段之后依次是门 / 移动组件 / 怪物 / **传送门**（顺序 = 实体注册表的顺序）。
老图（v1~v3）仍能读，portal_count 当作 0；要放传送门就得先用编辑器打开 → 另存为（写出去的一律是当前版本）。

**版本 4 → 5 的迁移**（新增实体「传送点」）：header 再多一个数量字段（五类实体），
传送点段接在传送门之后。老图（v1~v4）仍能读，waypoint_count 当作 0。
传送点存的是**一个点**（脚底坐标，与出生点/门落点同一套语义）：它是「地图信息」（大地图的目的地），
不是场景里的物件 —— 所以碰撞层/渲染层完全不认识它，只有大地图与编辑器认识。

> ⚠️ **header 里的 u32 个数不是单调的**：v1 = 8（多一个地刺数量）、v2/v3 = 7、v4 = 8（多一个传送门数量）、
> v5+ = 9（再多一个传送点数量）。所以长度算法不能用「是不是 v1」这种布尔判 ——
> `level_asset_header_u32_count(version)` 是唯一的算法，reader 与 writer 都调它，
> 否则 writer 写 36 字节 header 而长度只算 32，文件会被自己的长度校验拒掉
> （这个坑在 v4 当场踩到，错误表现是“能读但长度不对”）。
> 另外**每项的字节数也可能随版本变**（移动组件段从 28 → v6 的 40 → v7 的 40 但字段不同），
> 所以 `level_asset_compute_size()` 收的是 **version** 而不是「头有几个 u32」。

**版本 2 → 3 的迁移**（新增可消失平台 tile `V`）：**布局与 v2 完全一样**，只是 tile 段里多了一个合法字节。
升版本号的目的不是改布局，而是让旧程序**明确拒载**新图 —— 旧程序在 `src/level.cc` 的「未知 tile」
断言上会直接 abort，那不是值得保留的失败方式。两张图现在都是 v7（更早的版本也能读，
在编辑器里另存为就会变成当前版本）。

**版本 5 → 6 的迁移**（活动平台的轴改成任意方向 + 可设置伤害）：平台段从
「`min_x` / `max_x` / `velocity_x`」变成「两个端点 `point_a` / `point_b` + 沿轴 `speed` + `damaging`」。
旧图（v1~v5）仍能读，迁移规则是**按 `velocity_x` 的符号决定先朝哪端**：
`velocity_x < 0` → `point_a = (max_x, cy)`、`point_b = (min_x, cy)`，否则相反；`speed = |velocity_x|`、`damaging = false`。
这样老图跑出来的轨迹**逐帧不变**（水平轴 + 沿轴速度 = 原来的 x 速度），
`test/baseline.txt` 里那段「跨地刺时正好撞上平台底」的断言因此不需要重新取样 ——
迁移是否忠实就是靠它回答的（改完跑一次全量回归，基线仍 53/53 才算过）。

**版本 6 → 7 的迁移**（「活动平台」升级成通用的「移动组件」）：三件事 ——
①本体位置从**绝对中心**（`rect.center_x/center_y`）改成**轴上的参数 `t0`**：
中心 = `point_a + (point_b - point_a) * t0`（`level_asset_mover_rect()`，运行时与编辑器、校验共用这一份），
所以「本体不在轴上」这种状态在格式里存不下来；迁移时 t0 = 旧中心在轴上的投影（夹到 [0,1]）——
旧图的本体中心本来就在轴上（旧运行时第一帧会把它拉上去），所以推出来的就是它本来会在的位置。
②新增 `shape`（方形 / 圆形，语义见第 3 节）。③每个世界的数量上限从 1 放到 `LEVEL_ASSET_MAX_MOVERS`。
`v6` 与 `v5` 都能读：v6 直接拿它的两个端点，v5 先按上面那条规则换算成两个端点，再一起推 t0。
而 `v6` 的 `damaging`、`speed` 原样保留，所以 v6 图跑出来的轨迹也逐帧不变。

## 3. 当前约束与演进点

- 当前两个资产的 ID 与 `WorldId` 对应：`first.bin = 0`、`second.bin = 1`。编辑器应把这个 ID 当显式字段展示，不要依赖文件枚举顺序。
  - 编辑器由**文件名**推出世界 ID（只认 `first.bin` / `second.bin`，其它名字显示为「未知」）。
    再加世界 = 游戏侧「世界列表数据化」，不是加一个文件那么简单。
  - `include/shared/level.h` 有一条 `static_assert((u32)WORLD_COUNT == LEVEL_ASSET_WORLD_COUNT)` 把两个数字钉在一起。
- tile 是静态地形的真源（包括地刺格 `^`）；`level.cc` 在加载时合并同类 tile 为 `Platform[]`，
  并把每行相邻的地刺格合并成伤害矩形 `Level::spikes`。编辑器不应直接保存 `Platform`/地刺矩形。
- 可消失平台 `V` 也是 tile，但它在 `level.cc` 里被合并成**独立的一段** `Level::vanish_platforms`
  （不与实体/单向合并，否则它消失时会把邻居一起带走）。它的**相位与计时器是运行态**，
  住在 `GameState::vanish`（按块下标对齐），因此进快照、不进资产；时长是 `src/game.cc` 的两个常量，  触发要**连续踩住约 0.17s（10 个逻辑步）**才开始预告（离开立刻清零），之后**不可回退**：
  一旦进了预告期就一定走完「预告 → 消失 → 恢复」（离开也不会重置倒计时）。  而且**触发不可回退**（踩上就一定走完预告期，玩家离开/跳开都不重置）。
- **传送门**是有身份的实体（`LevelPortalAsset`），资产里只存「矩形 + 色号」，**相位与目标门下标是运行态**
  （`GameState::teleport`，进快照）。语义：**角色中心站在门矩形里时按上键**（`GA_UP`）才触发 ——
  判据是**中心**而不是碰撞盒相交（半只脚压上门会误触发）；落点 =「角色水平中心对齐门中心、脚底贴门底边」，
  门被埋进墙体时先顶上最近那层地面顶面（`teleport_depenetrate_up`）。玩家用法与用例见 `test/portal_pair.txt`。
- **传送点**也是实体（`LevelWaypointAsset`），但它只存**一个点**（脚底坐标）而不是矩形：
  它是「地图信息」（大地图的目的地，地图**之间**传送），不是场景里的物件。
  落地规则 = 与传送门同一条（水平中心对齐 x、脚底贴 y，埋进墙里同样顶上墙顶），
  所以两张图各摆 1 个就能用大地图来回传（见 `test/ui_map.txt`）。
- **移动组件**（`LevelMoverAsset`）是一个通用件：**形状 + 一条轴（两点）+ 沿轴速度**，每张图最多 `LEVEL_ASSET_MAX_MOVERS` 个。
  轴可以任意方向（水平 / 竖直 / 斜着），方向 = 先朝 `point_b` 走、到端点反向；`speed` 是**沿轴**的速度（不是某个分量）。
  运行时本体中心 = 轴上的参数 `t`（`update_movers` 只做「t 加减 speed*dt/轴长 + 夹到 [0,1] 反向」，
  **不做逐分量推演** —— 斜轴会跑偏）；`t`、`direction` 以及本体的当前矩形都是**运行态**（进快照），
  资产里只有端点、起点 t0、尺寸与速度。
  形状决定行为（这是它与「一块会动的地形」的区别）：
  | 形状 | 碰撞 | 行为 |
  | --- | --- | --- |
  | 方形平台 | 实心 | 可站、**驮着走**（两个轴都驮）；`damaging` 打开时「被挤住 / 压住」才受伤（驮着走安全） |
  | 圆形 | 实心（不可穿过） | **不驮人**，恒定伤害：只要碰到就回出生点（`damaging` 对圆形无意义） |
  实测（临时用例，验完已还原）：竖直方形平台把角色从 -1343.6 带到 -1143.6（2s × 100px/s）；
  冲刺撞圆形 → 回出生点 x = 288，同一位置换成方形（不伤害）→ 只被挡住 x = 404.8；
  方形从头顶压下来时 `damaging = 1` → 回出生点 288，`= 0` → 被压在原地 309.3。
- 有身份的物件（门/移动组件/怪物/传送门/传送点）的种类与字段位置收在**实体注册表**里（见第 5 节），
  运行时与编辑器共用一份描述。地刺不是实体，它是 tile。
- 移动组件与门、传送门一样：**当前世界**的那一份被实例化，换世界时重建（见 `enter_world`）。
  怪物仍然是「每个世界只实例化一个」（`LEVEL_ASSET_MAX_MONSTERS`），解除它要动 `GameState` 的容器，与格式无关。
- 能量波不属于关卡资产：当前原型的运行时池最多容纳 8 枚，普通门切图时会清除，因此不会跨世界遗留。
- 改格式时提升 `LEVEL_ASSET_VERSION`，新增明确的读取分支或拒绝旧版本；不要“猜测”旧字节布局。

## 4. 写入与语义校验（2026-09-22 随编辑器一起加）

### 4.1 `level_asset_save()` —— 写入的三步

1. 写 `<路径>.tmp`（**原文件全程不动**）；
2. 立刻 `level_asset_load` 读回临时文件，并**逐字段与内存中的资产比对**；
3. 通过后才 `file_move_replace()` 覆盖原文件。

任何一步失败都删临时文件并返回 false。第二步不能只做「读取器能接受」—— 写错一个字段一样是个合法文件，
所以必须是逐字段比对（比较时也**不能 memcmp 结构体**：padding 未初始化）。

实现上与 reader 逐字段对称，并且**共用同一个 `level_asset_compute_size()`**：文件总长度的算法只有一处，
「写出来的文件自己读不回来」这类漂移因此没有生存空间。

### 4.2 `level_asset_validate()` —— 「能读」不等于「能玩」

`level_asset_load` 只能验格式与范围（长度、枚举、`shape < LEVEL_MOVER_SHAPE_COUNT`、`damaging <= 1`），
它**结构性无法**知道「每个世界只允许一个怪物」这类游戏侧约束 —— 那些约束在这里，规则表见
`include/shared/level_asset.h` 的 `LevelAssetIssueKind`，实现在 `src/shared/level_asset.cc`。

分两级：**ERROR**（关卡不该被保存，游戏侧一定有问题）与 **WARN**（能跑，但建议看一眼）。

| 级别 | 检查 |
| --- | --- |
| ERROR | 移动组件 ≤ 8 个、怪物 ≤ 1 个（游戏侧是 `assert`，多了直接 abort） |
| ERROR | 出生点恰好 1 个（多个时 `level.cc` 是「最后一个赢」，静默） |
| ERROR | 矩形尺寸为零/负、数值含 NaN/Inf、移动组件两个端点重合（没有可走的轴）、矩形整个落在关卡外 |
| ERROR | 门的 `target_level` 越出世界范围，或指向自己 |
| WARN | 出生点落在实体（门/移动组件/怪物）的矩形里、出生点正下方没有支撑 |
| WARN | 移动组件的 `speed <= 0`（走不动；运行时把它当作 0 位移，不是错误） |
| WARN | 移动组件的 `t0` 超出 [0,1]（运行时夹取；等价于「从端点出发」） |
| WARN | 同一列上下两块平台的**行差只有 2 格**（中间只空 1 格 = 64px，角色碰撞盒约 90px 挤不进去）。行差 1 是实心块（墙/地面），正常 |

两个设计点：

- **数字只有一处**：`LEVEL_ASSET_MAX_MOVERS` / `LEVEL_ASSET_MAX_MONSTERS` /
  `LEVEL_ASSET_REQUIRED_SPAWN_TILES` / `LEVEL_ASSET_MIN_ROW_DELTA` / `LEVEL_ASSET_WORLD_COUNT`
  在 `include/shared/level_asset.h`，游戏侧的 assert 引用的是同一批常量（本工程在手柄按钮映射上踩过「一表一实现」的坑）。
- 校验**不编译、不分配**（`LevelAssetsIssues` 是固定数组，可以直接放栈上），所以编辑器可以每帧跑它做实时提示；
  要编译的是「诊断」（合并碰撞体、格→碰撞体反查），那是按钮触发的，见 `editor/README.md`。

### 4.3 给未来加字段的清单（以「怪物血量」为例）

1. 先改游戏：`Monster` 加字段 + 玩法侧消费逻辑；
2. **加进 `GAME_STATE_PERSISTENT_FIELDS`**（`include/game.h`）—— 漏了不会报错，表现是回放/脚本开头几帧对不上；
3. 改共享层：`LevelMonsterAsset` 加字段 + reader/writer 各一行 + 版本升 2 + 校验加规则；
4. 旧 `.bin` 的处理：建议在 reader 里加一条 v1→v2 迁移（按默认值补齐），而不是让作者重画；
5. 编辑器几乎不用改（属性面板加一行控件）—— 前提是属性面板就是「结构体参数的直译」。

关卡指纹（`game_level_fingerprint`）会随字段变化，所以旧存档与旧磁带**都会**被拒载，这是设计而不是 bug。

编辑器自身的使用说明见 `editor/README.md`。

## 5. 实体注册表：实体种类的唯一来源

`include/shared/level_asset.h` 的 `LEVEL_ASSET_ENTITY_TABLE` 一行描述一种实体：

| 字段 | 含义 |
| --- | --- |
| `name` | 中文名 —— **界面与校验消息共用同一份**，不再是两处字符串 |
| `array_offset` / `count_offset` | 数组指针与数量在 `LevelAsset` 里的位置（`offsetof`） |
| `element_size` | 元素大小 |
| `rect_offset` | `Rect2D` 在元素内的偏移；`LEVEL_ASSET_NO_RECT` = 这种实体没有矩形（门） |
| `max_count` | 运行时限几个（引用 `LEVEL_ASSET_MAX_*` 常量；不限就是 `UINT32_MAX`） |

配三个读访问器（`level_asset_entity_count` / `_data` / `_at` / `_rect`与可写版 `_rect_mut`）。

**它消掉的是「加一种实体要改 4-8 处、漏一处静默出错」这回事**：校验里的数量上限、
矩形通用检查（有限值 / 非退化 / 越界）、出生点重叠、编辑器的命中测试、列表显示、
实体数组的增删 —— 全是表驱动。加一种实体 = 表加一行 + 属性面板加一个 `case`。

边界说清楚：

- 游戏的**运行时**（`Level` / `GameState`）不消费本表 —— 每类实体有不同的运行字段与初始化逻辑，
  强行统一只会多一层间接。本表服务的是**编辑语义**这一层。
- 属性面板仍然按类型手写（真的字段不同），但已经把控件形态收成三个 helper
  （`f32` / `Rect2D` / 枚举），加一个字段 = 加一行控件。
- 表里的 `max_count` 与游戏侧 `assert` 引用的是**同一批常量**（`LEVEL_ASSET_MAX_MONSTERS` 等），
  所以「编辑器允许 1、游戏断言 1」这种两份数字的漂移没有生存空间。
