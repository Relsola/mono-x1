# 存档系统（save）

`include/save.h` + `src/save.cc`。**这是正式系统，不是调试设施**：它不带任何 `MONO_DEBUG_*` 门控，
将来就是游戏的存盘点 / 手动存档 / 读档入口。现在先被调试用的「磁带」（录制回放与输入脚本）当底座。

## 1. 职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `game_state_save/load`（`include/game.h`、`src/game.cc`） | **哪些字段算状态**（`GAME_STATE_PERSISTENT_FIELDS` 字段表）、枚举/bool 是否合法、读档后把渲染插值历史对齐 | 文件格式、校验 |
| `save`（本模块） | 文件布局、三重校验、路径即存档槽 | 状态语义、槽位编号、存档菜单、存档时机 |
| 磁带（`include/debug/replay.h`） | 存档点引用 + 输入 + 断言（含 `save_state` / `load_state` 两个操作） | 状态序列化本身 |

状态快照 `GameStateSnapshot`（`include/game.h`）是唯一的「可序列化状态」定义，
**存档、录制回放、输入脚本共用同一份**。它由 `GAME_STATE_PERSISTENT_FIELDS`（同一文件里的字段表）**生成**：
结构体、`game_state_save`、`game_state_load` 三处同源，所以「结构体加了字段、save/load 忘了抄」
这种不对称在结构上不可能发生 —— 想加一个进存档的字段，就在表里加一行。
三道防线（按代价从低到高）：

| 防线 | 手段 | 能拓住什么 |
| --- | --- | --- |
| 结构 | 字段表生成结构体与读写（`include/game.h`） | 三处不同步（编译期就不可能） |
| 运行期 | `game_state_snapshot_selftest`（启动时跑一次） | save→load→save 不逐位一致（load 漏装某位） |
| 行为 | `test\run_tests.bat` 的确定性守卫（两遍 trace 对拍） | **该进表却漏了**——这两个字属于语义判断，只能靠行为层面拓 |

## 2. 文件格式

```
SaveHeader（20 字节） + GameStateSnapshot（按结构体字节序直接写，不做重排）
```

| 字段 | 说明 |
| --- | --- |
| `magic` | `"MSAV"`（小端 0x5641534D）：一眼看出这不是别的文件 |
| `version` | 格式版本，当前 1。语义变了就 +1（旧文件明确拒载，不做猜测式迁移） |
| `payload_size` | `sizeof(GameStateSnapshot)`：结构体增删字段、甚至换编译器导致对齐变化都能拦下 |
| `level_fingerprint` | 写档那一刻的关卡几何指纹，见下 |
| `checksum` | 负载的 FNV-1a 32（参数与关卡指纹共用 `core.h` 的 `FNV1A_*`，不能各写一套） |

**三重校验，任何一条不过都拒载** —— 宁可报错，也不拿错位的字节去还原现场：

1. `magic / version / payload_size`：格式换代或快照结构改动；
2. `level_fingerprint`：关卡几何变了（改了 `.bin` 资产或 `level.cc` 的合并规则）。
   存档里记的是「那个关卡里的位置与实体状态」，拿它去解释新关卡会得到卡在墙里、
   掉出世界这类无从排查的怪现象 —— 所以这里直接拒载，而不是让断言在几十帧后才失败；
3. `checksum`：文件被截断或损坏。

三条路径的实测输出（`--load` 一个被动过手脚的文件）：

```
[ERROR] save: build/_bad_fingerprint.sav was written for another level layout (6859b851, now 6859b8ae) — regenerate it
[ERROR] save: build/_bad_checksum.sav is corrupted (checksum mismatch)
[WARN ] save: cannot open build/_no_such_file.sav
```

### 关卡指纹怎么算

`game_level_fingerprint(const GameState *)`（`src/game.cc`）把**所有世界**的

- 出生点与边界（`bounds`）
- 每个碰撞矩形（中心 + 半宽高）与碰撞语义（实体 / 单向）
- 地刺格（tile；运行期合并成的伤害矩形也进指纹）
- 移动组件与怪物的出生描述（轴 / 形状 / 尺寸 / 初速）
- 左右门的落点与目标世界

逐字段哈希成 32 位值。两个细节：

- **只哈希字段值，不哈希结构体内存**：结构体的填充字节不保证被初始化，按块哈希会得到不确定的值
  （同一个状态两次运行算出不同的指纹）。所以 `core.h` 提供了 `fnv1a_value`。
- **两个世界都参与**：存档里记着「当前在哪个世界」，任一张地图改了都该让旧存档失效。

## 3. API

| 函数 | 说明 |
| --- | --- |
| `save_write(path, game_state)` | 抓一份快照并写盘（自动创建缺失的父目录） |
| `save_read(path, game_state, out)` | 只读回快照；`game_state` 只用于取「当前关卡指纹」做第 2 重校验。失败时 `*out` 保持原样 |
| `save_restore(path, game_state)` | `save_read` + `game_state_load`：脚本、回放与 `--load` 都走这一条 |

读档失败时调用方可以「沿用当前状态继续跑」——`--load` 就是这么做的（`WARN` 之后从出生点开始），
而**磁带不行**：磁带的世界必须与录制时逐位一致，所以它读档失败就直接拒绝开始（见 `docs/input-script.md`）。

## 4. 命令行

| 开关 | 作用 |
| --- | --- |
| `--load <路径.sav>` | 启动即读档。与 `input_script` 同时用时以脚本的存档点为准 |

## 5. 会丢什么、不会丢什么

读档只恢复 `GameStateSnapshot` 覆盖的部分。**丢的必须是「不影响后续演化」的量**：

| 类别 | 例子 | 是否进存档 |
| --- | --- | --- |
| 跨帧会变、且影响后续演化的状态 | 玩家位置/速度/各计时器/能力次数、相机、世界、移动组件、怪物、能量波、伪时停、门过渡 | ✅ 进 |
| 每帧从当前状态重新长出来的量 | 渲染插值用的 `prev_*`、动画当前帧、音频播放相位、纹理句柄 | ❌ 不进 |
| 策略 | 相机档位（由场景决定、跨帧不变） | ❌ 不进 |

给 `GameState` 加字段时先判断它属于哪一类：属于第一类就必须同时加进 `GameStateSnapshot`
与 `game_state_save/load`，**漏了不会报错**，只会让回放/脚本开头几帧对不上。

## 6. 与磁带（调试）的关系

```
录制（F5）:  存当前状态 → 写 build/replay_state.sav ─┐
                                                     ├─→ 磁带（存档点路径 + 输入变化点 + 断言）
脚本（input_script） / 回放（F6）: 读那个 .sav → 磁带喂输入 → 磁带求值断言
```

分工是刻意的：**「世界一模一样」由存档系统负责，「输入一模一样」由磁带负责**，
两边可以各自独立演进。这解决了旧设计撑不住的地方 —— 当时快照是以结构体字节的 hex
内嵌在脚本文本里的：

> ~~`initial_state v1 <762 字符 hex>`：与编译器/字段布局死绑、没有版本与关卡校验，
> 改一个字段就全体失效（脚本文本的行缓冲必须跟着快照大小一起长）。~~
> 2026-09-22 已删除：改成引用磁盘上的 `.sav`（`docs/input-script.md` 记了新格式）。

## 7. 将来正式化时缺的东西（现在就别做）

- **多存档槽 / 存档菜单**：路径即槽，槽位编号与 UI 都是上层策略；
- **自动存档时机**：什么时候存（过门、重生、检查点）属于玩法决定，不属于本模块；
- **版本迁移**：现在版本不匹配一律拒载。真要迁移，得先有「读旧字段、补默认值」的映射表；
- **压缩 / 校验以外的完整性**：目前负载只有几百字节，压缩是纯浪费；
- **存盘点与关卡资产的绑定**：现在靠指纹拒载，将来若要做「关卡检查点存档」，
  需要在关卡资产里放检查点实体，并让检查点也成为指纹的一部分。

## 8. 验证方式

- 正常链路：`test/save_roundtrip.txt`（常驻用例）—— `save_state` → 接着跑 20 帧 →
  `load_state` 回到那一刻，容差 0.05px 的逐位一致断言，再验证读档后的演化。
  它不依赖任何外部存档文件，跑法见 `docs/input-script.md`（或直接跑 `test\run_tests.bat`）；
- 拒载链路：把 `.sav` 的指纹字段（偏移 12..15）或负载里的任意字节改掉，用 `--load` 跑一次，
  日志里应出现上面那三条错误之一，且游戏从出生点继续（不崩、不静默接受）。
